# 賽前時程

## 9/8 19:00–22:00（四人）

目標：建立一致工具環境與共同操作方式。

- 確認 GitHub、Codex CLI、Python 與個人 credits 的存取方式。
- 選定並凍結 Matt Pocock skills 清單與來源 commit。
- 共同示範一次 Issue → Pull Request 流程。
- 建立與參賽內容無關的練習 repo。
- 確認主辦方待回覆問題與負責追蹤方式。

## 9/9 19:00–22:00（咏宸、于喬、昊祁）

目標：用實際操作找出手冊缺口。

- 由 Vibe Coding 經驗較少的成員完成小任務。
- 測試團隊實際會使用的開發環境、連線與故障回報流程。
- 模擬一個失敗並依 troubleshooting 流程整理證據。
- 修改所有需要口頭補充才能完成的手冊步驟。

## 9/10 19:00–22:00（四人）

目標：產生交接包候選版本。

- 進行限時 dry run。
- 驗證多人 branch、Pull Request、合併與衝突處理。
- 題目若已獲回覆，完成產品規格與最小驗收條件。
- 依 [交接包驗收](../../build-handoff/ACCEPTANCE.md)建立候選版本。

## 9/11（全員，時段待確認，至少 2–3 小時）

目標：完整走完交接流程，通過後凍結。

- 從交接包候選版本建立全新 rehearsal repo。
- 使用與參賽題目無關的小型任務。
- 每位成員實際完成自己的步驟，不以觀看示範代替。
- 模擬 Codex/API、網路、GPU 或 Git 故障及降級。
- 記錄所有模糊、失敗與需要口頭解釋之處，修正後重測。
- 全部通過後標記凍結版本；否則保留候選狀態與未通過項目。

## 9/12 比賽日

以下時程依主辦方通知執行。

- 09:00：入場報到。
- 09:40：開場與流程說明。
- 10:35 前：建立全新的實作 repo；此時僅能完成準備，不得撰寫或搬入競賽程式。10:35 起，開發與提交紀錄的 timestamp 必須符合正式時限。
- 10:35–17:35：唯一可正式開發與提交的時段。單向複製凍結交接包一次，並以實作 repo 作為產品規格的唯一真實來源；不複製規劃 repo 的研究與長篇手冊。
- 12:30：午餐。
- 建議 17:10：隊內功能凍結，保留提交緩衝時間。
- 17:35 後：不得再開發或提交；依序進行第一輪評選（17:50）、前五名第二輪評選（19:45）、頒獎（21:10），並於 21:45 結束。
- 現場角色：指定一人負責額度追加與規則通知，立即記錄並同步可能影響團隊決策的變動。
