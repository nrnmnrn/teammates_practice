# 驗收與環境訪談紀錄

日期：2026-09-10
輪次：第一至第八輪

本文件記錄團隊訪談中的暫定共識，供後續討論驗收樹、環境與動態認領工作使用。它不是正式產品規格；正式交接仍只使用 `build-handoff/`。本紀錄不表示產品已驗收，也不表示產品方向已凍結。

## 已同意事項

### 驗收

每項驗收必須具備：

- 操作：如何執行檢查。
- 預期結果：通過時應看到的結果。
- 驗收清單所記實際結果：本次操作或確認的結果。

三者齊備，且實際結果符合預期，該項才可標示為「通過」。未執行者標示為「未驗證」。功能驗收通過後，仍須進行完整流程驗收。

### 共同確認

由當下可參與的隊員共同確認驗收結果並記錄結果。不要求全員到齊，也不指定永久審核人。最終展示由全隊確認。

#### Q4：`uv` 環境

團隊共用 Python 版本、依賴定義及 `uv.lock`；每位隊員使用獨立 `.venv`。既有 UI 相容性仍待驗證。

#### Q5：執行基準

本產品交接移除 A6000 專屬準備與驗收要求，改以 CPU 作為執行基準。歷史教材保留；不宣稱效能已驗證。

#### Q6：工作認領

未認領工作可由隊員自行登記並開工。已有人處理時，先協調；結果由隊員共同確認。此共識不變更合併或發布權限。

## 第三輪紀錄

### 已同意事項

#### Q3：驗收證據

驗收須經實際操作或確認，結果符合預期，並由當下隊員共同確認。現場觀察可作為通過依據，驗收清單記錄結果。

證據形式由團隊決定，不強制截圖、短片或附件。難以重現、有爭議，或需供不在場隊員查看時，再考慮附件；附件不是強制要求。未執行者不可標示為通過。

## 第四輪紀錄

### 已同意事項

#### Q7：驗收樹

驗收樹為「整體交付」至「完整功能流程」至「正常、邊界、失敗案例」。每個完整流程跨操作、執行結果及畫面更新。現階段不為每個分支另建子規格。

#### Q8：必要案例未通過

必要案例未通過時，記錄問題，整體驗收為未通過。不可因時間不足自行刪除案例；縮減範圍須由團隊明確決定並更新規格。預期的錯誤拒絕若符合規格，仍算通過。

#### Q11：修改後重驗

修改後，重驗受影響案例與相關串接；無關結果保留。最終展示前，執行完整主流程。

#### Q12：共同確認

作者可自行驗收，並標示待共同確認。至少另一位隊員參與確認後，才可標示為通過；人選不固定。最終展示由全隊確認。

## 第六輪紀錄

### 已同意事項

#### Q10：子 PRD 作為最小驗收單位

子 PRD 是最小驗收與勾選單位。每份子 PRD 定義一項完整且可確認結果的功能；正常、邊界與失敗案例包含其中，作為審查依據，不各建驗收文件或批准流程。

審查包含實際確認子 PRD 功能結果，不只是閱讀程式。子 PRD 符合內容、審查通過且開發變更已合併後，該子 PRD 驗收通過。

所有子 PRD 通過後，仍須進行整體串接與最終展示確認。合併權限不變。

## 第七輪紀錄

### 已同意事項

#### Q13：子 PRD 作為最小合併單位

子 PRD 也是最小合併單位，保持小而完整；內部可由多人分工。整份子 PRD 完成、功能結果已確認且審查通過後，才可合併；合併即完成該子 PRD 驗收。

不可只因其中畫面完成，就在後端未完成時先合併部分變更。既有合併權限不變；所有子 PRD 合併並驗收後，仍須完成整體串接與最終展示確認。
