# 2025 Recife Vibe Hack（UFPE；ICSE-SEET 2026 經驗報告）

研究日期：2026-09-09
資訊分類：活動、參與者／作品與研究結果分別列為「已確認資訊」或「參考性先例」；研究推論另行標示。本案不是 Sea × OpenAI 台灣站規則、產品需求或團隊決定。

## 研究問題

Recife 的 Universidade Federal de Pernambuco（UFPE，巴西公立大學）Vibe Hack 如何在單日以自然語言驅動 AI coding，讓多人團隊從想法走到可展示原型？有哪些責任、協作、整合、返工與時間節奏證據可供本批比較？

## 基本資料

- **活動／地點／日期：** Vibe Hack；CIn-UFPE（Centro de Informática）於 Recife，首屆於 2025-07-26 舉行。UFPE 官方招生公告確認日期、地點、主辦教師與開放不同程度學生。[UFPE 官方公告，2026-09-09 查閱](https://www.ufpe.br/en_US/ascom/noticias/-/asset_publisher/O3Odar12gQTr/content/primeira-edicao-do-vibe-hack-abre-inscricoes-para-interessados-em-vibe-coding/40615)
- **參與規模：** 論文稱 31 名本科生、9 隊，其中 4 隊為跨領域；每隊 3–4 人，分為 CIn／computing-only 與 mixed categories。[論文 HTML，2026-09-09 查閱](https://arxiv.org/html/2512.02750#S3.SS1)
- **研究材料：** Gama et al. 的 ICSE-SEET 2026 論文（DOI 10.1145/3786580.3786992；arXiv 版本 2025-12-02）報告活動觀察、27 份完整 exit survey 與 10 位參與者訪談。[論文頁，2026-09-09 查閱](https://arxiv.org/abs/2512.02750)
- **成果：** UFPE 官方結果公告確認 mixed category 的 PLURI 及 CIn-only 的 IRIS Map 得獎，並列出隊員與作品用途。[CIn-UFPE 官方結果公告，2026-09-09 查閱](https://portal.cin.ufpe.br/2025/08/05/primeira-edicao-do-vibe-hack-do-cin-ufpe-premia-projetos-voltados-a-inclusao/)

## 已確認資訊

- UFPE 官方公告確認首屆 Vibe Hack 於 2025-07-26 在 CIn-UFPE 舉行，由 Kiev Gama、Vinicius Garcia、Filipe Calegario、Luiz Augusto Morais 推動，開放不同程度學生。[UFPE 官方公告](https://www.ufpe.br/en_US/ascom/noticias/-/asset_publisher/O3Odar12gQTr/content/primeira-edicao-do-vibe-hack-abre-inscricoes-para-interessados-em-vibe-coding/40615)
- 論文的活動設定稱其為實體、包容、單日 vibe coding hackathon；31 人分成 9 隊，4 隊跨領域，隊伍 3–4 人。[論文第 3 節](https://arxiv.org/html/2512.02750#S3)
- 論文記錄活動流程：08:30 報到、09:00 說明、09:45 組隊、10:00 發想、11:00 提交題目並開發、13:00 休息、16:00 pitch、17:30 頒獎閉幕；作者另在摘要稱約 9 小時，正文有「8-hour format」表述，時間長度存在內部用語差異。[論文第 3.1 節](https://arxiv.org/html/2512.02750#S3.SS1)
- 作者觀察到部分隊伍自組 leader、lead programmer、designer；問卷回覆中 11 人提到 leader、14 人提到 lead programmer、12 人提到 designer，另有隊伍採較不正式的角色。[論文第 5.2.3 節](https://arxiv.org/html/2512.02750#S5.SS3)
- AI interaction 有兩種模式：單一共享 instance／由一人操作，或多人使用各自／多個 instance 互相比較；15 位回覆者稱使用多個 instance 比較結果，16 位稱整場持續使用 AI。[論文第 5.2.3 節](https://arxiv.org/html/2512.02750#S5.SS3)
- 論文訪談記錄實際 prompt coding 與協作：有隊伍把可由 prompt 解決的工作與需手動改 code 的工作分開；有隊伍把 prompt 集中在 shared Google Docs；也有人用 prompt master 在多個服務平行測試，再迭代修正。[論文第 5.3.5 節](https://arxiv.org/html/2512.02750#S5.SS5)
- 論文記錄多工具 pipeline：FigJam／Google Stitch 做視覺原型，ChatGPT／Grok／Gemini 做 prompt polishing，Lovable／Cursor／V0 生成 app，再以 Copilot 等工具修整；這是作者依訪談與觀察的活動描述。[論文第 6.1.4 節](https://arxiv.org/html/2512.02750#S6.SS1)
- AI 輸出並非直接交付：問卷顯示對 AI code 品質與可維護性信任有限，修改 code 或追加 prompt 的返工普遍；多數人認為成品可運作但仍有 bug。[論文第 5.2.4 節](https://arxiv.org/html/2512.02750#S5.SS4)
- 訪談記錄整合與穩定性問題：導覽／頁面整合可能產生不良結構，輸出有時可用、有時失效，且未必符合 commit／production standards。[論文第 5.3.6 節](https://arxiv.org/html/2512.02750#S5.SS6)
- UFPE 官方結果公告確認 PLURI（Dayane Lima、Douglas Araújo、Maria Eduarda Marrocos）獲 mixed category 第一名，IRIS Map（Rafael Samico、Antonio Rodrigues、Jonathas Silva）獲 CIn-only 類別第一名。[CIn-UFPE 官方結果公告](https://portal.cin.ufpe.br/2025/08/05/primeira-edicao-do-vibe-hack-do-cin-ufpe-premia-projetos-voltados-a-inclusao/)

## 參考性先例

### 關鍵決策、限制、取捨與結果

**來源直接陳述：** 活動以「對初學者友善、單日、可快速原型」為設計取向。隊伍自行分配 leader／lead programmer／designer 或採較鬆角色；prompt、Kanban 與 shared document 用來分配人與 AI 工作；多工具 pipeline 讓團隊先做視覺原型，再整理 prompt、生成 app、最後修整。時間、credit／token 限制與不穩定輸出促使隊伍減少大而模糊的 prompt、追加 prompt 或手改 code。這些描述均來自作者對觀察、問卷與參與者訪談的綜合報告。[論文第 3.1、5.2.3、5.3.5–5.3.8、6.1.4 節](https://arxiv.org/html/2512.02750)

**研究推論：** 本案支持把「共同 prompt／可讀的責任分界／人為驗收」視為可討論的多人 AI coding 候選；也顯示快速原型與生產級品質之間存在取捨。沒有版本歷史、獨立對照組或評審逐項理由，不足以說明任何一項做法造成得獎。

### 候選實務：用共享意圖與明確人機責任，管住多工具並行

- **來源證據：** 參與者描述 shared Google Docs、prompt master、Kanban，以及把 prompt 可解工作與需手動改 code 工作分開；論文也報告多個 AI instance 比較結果，並記錄錯誤、整合失敗與追加 prompt／手改 code 的返工。[論文第 5.2.3、5.2.4、5.3.5–5.3.7 節](https://arxiv.org/html/2512.02750)
- **研究推論：** 未來多人 AI coding 可討論以一份共享產品意圖／prompt log 作語意對齊，以明確標記「AI 建議、人工裁決、人工驗證」；此為研究候選，不是本隊決定。
- **何時值得討論：** 至少兩人同時使用 AI、工作會跨工具或需要合併輸出，且團隊希望降低語意漂移與重複返工時。
- **未來規劃問題：** 誰維護唯一意圖與驗收標準？哪一人／哪一階段有權裁決 scope？每次 AI 輸出要留下什麼可重播證據？何時凍結 prompt 與 demo 版本？
- **限制／風險：** 本案是單一大學、單日、特定工具組合的 experience report；主要資料為匿名問卷與訪談，沒有公開 commit、prompt log、責任表、衝突紀錄或可操作作品。因此不可量化共享文件是否真的降低返工，也不能把訪談感受當成通用成效。
- **待核實項目：** 尚不知各隊的實際整合頻率、誰負責最終 merge／驗證、是否有共用 repo、prompt log 是否保存、哪些功能因 token／時間被放棄，以及兩個得獎隊是否採相同流程。
