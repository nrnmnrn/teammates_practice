# 評選規劃判準

此表為隊內規劃判準，非官方 rubric。四名稱來自隊內記錄；公開定義與權重仍待主辦方核實。

## 讀取順序

預設僅讀本檔。需活動事實讀[比賽資訊](README.md)。需來源與評審公開訊號，再讀[主題摘要](../research/topics/2026-09-taiwan-judge-public-signals.md)及其個案連結。

| 隊內規劃準則 | Agent 應問 | 最低展示證據 |
| --- | --- | --- |
| 問題框架（problem framing） | 誰在何情境遇何問題？為何現有方法不足？成功長何樣？ | 一個具體情境；問題、對象、可見結果之連續 demo。 |
| 構建品質（build quality） | 核心流程可否現場完成？失敗時如何處理？ | 可運行端到端核心流程；一項已知限制或失敗邊界。 |
| 思考深度（depth of thought） | 為何選此解法？捨棄何選項？風險何在？ | 一項關鍵取捨及理由；適用範圍與限制。 |
| Codex 應用（Codex usage） | Codex 協助何工作？人如何驗證或修正輸出？ | 一個可指認的 Codex 產出，及其被採用、修改或驗證之結果。 |

勿由此表推測評分、權重、提交格式或任何評審偏好。主辦方若發布直接定義，以其為準並更新本檔。
