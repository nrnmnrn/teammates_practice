# 比賽資訊

本頁記錄 Sea x OpenAI Codex Hackathon Taiwan 的正式活動資訊、隊內通知與仍待確認的事項。若不同通知之間有差異，以主辦方給本隊的最新正式通知為準，並保留差異。

## 已確認資訊

### 官方活動資訊

以下內容整理自隊內提供的官方正式資訊，並保留官方活動頁作為查證入口：

- 活動名稱：Sea x OpenAI Codex Hackathon Taiwan。
- 舉辦日期：2026-09-12（星期六）。
- 較早官方活動資訊曾列活動時段為 09:00–21:30；此為較早版本，已由本隊收到的最新決賽時程取代。兩者相差 15 分鐘，差異保留供查核。
- 活動地點：台北國際會議中心（TICC）。
- 官方活動頁：<https://shopee.tw/m/seaxopenai-hackathon-tw>。
- 報名期限：即日起至 2026-08-26。
- 入選通知日期：2026-09-01。
- 活動定位：Sea 與 OpenAI 在台灣舉辦的 Codex Hackathon，讓開發者、學生、新創團隊及科技人才使用 OpenAI Codex，透過技術指導與團隊實作，將構想轉化為能解決真實世界問題的 AI 應用。
- 參賽對象：軟體開發者、學生與新創團隊、科技人才，以及對 AI 應用開發有興趣的個人。
- 核心工具：OpenAI Codex。
- 預期成果：可實際運作的 AI 應用 prototype 或 solution，並能展示其對真實世界問題的解法。

### 官方評審資訊

- 評審團由 Sea 與 OpenAI 的資深技術主管組成，晉級決賽隊伍須展示創新成果與應用構想。
- **David Chen**：Sea 共同創始人暨蝦皮購物首席產品官（Chief Product Officer at Shopee）。負責蝦皮購物的產品策略與發展方向，並推動 Sea 集團在 AI 技術與開發者生態的投資與合作；他重視社群共同學習、實驗與建構對創新的作用。
- **Oliver Jay**：OpenAI 國際業務主管（International Business Lead at OpenAI）。負責 OpenAI 的全球業務拓展與合作策略；他指出台灣在 Codex 採用與使用活躍度方面已進入全球前十大市場，並期待透過黑客松支持台灣開發者運用 Codex 解決真實世界問題。
- **Thibault Sottiaux**：OpenAI Codex 負責人（Head of Codex at OpenAI）。領導 Codex 的產品開發與策略，並參與亞太開發者生態建設，專業涵蓋 AI 驅動的程式碼生成、開發者工具與開發流程優化。
- 隊內以問題框架（problem framing）、構建品質（build quality）、思考深度（depth of thought）、Codex 應用（Codex usage）四個名稱規劃展示。這些名稱、評審公開訊號及隊內推論只供準備方向參考，不代表台灣站官方評選方式；見[評選規劃判準](judging-planning-rubric.md)。

### 本隊收到／已向主辦方確認

- **來源：主辦方最新決賽時程與回覆（收到日期待補）**。當日時程為：09:00 入場報到、09:40 開場、10:35 Coding 開始、12:30 午餐、17:35 停止開發與提交、17:50 第一輪、19:45 前五名第二輪、21:10 頒獎閉幕、21:45 結束。
- 正式開發窗口為 10:35–17:35，共七小時；所有開發與提交須在此窗口內完成。
- 開發方向：自主且具適應能力的 AI（Autonomous & Adaptive AI）。
- 可在賽前建立規格文件及安裝 skill、MCP、plugin；參賽 repo 在賽前不得建立程式碼。
- 題目可在正式開發開始前調整，無須另行申請。
- 參賽 repo 必須全新建立；開發紀錄的 timestamp 必須符合正式開發時限。
- 每位參賽者可獲得 USD 100 API credits 及 USD 100 Codex credits，供 Hackathon 開發使用。
- 原額度用罄後，團隊可依實際開發需求到舞台左側 IT 諮詢桌申請，每次 USD 100；主辦方在活動期間提供協助。
- 可在比賽中遠端使用團隊實驗室的兩張 Ampere 架構 NVIDIA RTX A6000；主辦方已同意。
- PPT 為選用；報告時間與評選形式將在賽前、Coding 開始前統一說明，細節尚未確認。

> 上述內容依本隊收到的主辦方資訊記錄。僅記錄可查核的來源描述與收到日期；不得在本 repo 儲存原始 email、個資或私人訊息。

### 官方活動要求的解讀

- 官方資訊要求參賽者使用 Codex 完成產品與展示；因此本隊的 demo 必須能說明 Codex 在需求理解、實作、測試或修正中的實際作用。
- 隊內規劃以四項名稱整理可展示證據；這不是官方評分宣稱。見[評選規劃判準](judging-planning-rubric.md)。
- 隊內決定不把未知的台灣站評分比重列為待確認或產品前提；若主辦方之後直接公布，仍依更新規則記錄。
