# 基本觀念

## Prompt 不是規格

「幫我做登入頁」只是一個願望。可執行的規格至少要說明輸入、成功結果、失敗結果及驗收方式。Agent 若需要猜測，通常會猜錯。

## Context 是有限資源

Agent 看到的對話、文件和程式碼越多，不代表效果必然越好。只提供目前任務需要的資料；新任務開新對話，並用 issue 或規格重新建立必要 context。

## 測試是回饋，不是儀式

測試讓 agent 知道改動是否真的達成需求。先看到新測試因缺少功能而失敗，再寫最少程式使其通過，最後整理程式結構。

## Diff 是人類的驗收介面

Diff 顯示這次新增、刪除與修改的內容。提交前逐段確認：是否只改了必要檔案、是否偷偷移除檢查、是否加入秘密資料、測試是否真的驗證需求。

## Skill 是流程說明

Skill 不是魔法能力，而是一組讓 agent 重複採用同一工作方法的指示。先選對流程，再給清楚任務；不要把多個用途相近的 skills 同時丟給 agent。
