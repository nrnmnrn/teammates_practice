# 故障與降級處理

## 通用規則

1. 保存完整指令、錯誤文字、時間及最近一次成功狀態。
2. 一次只改一個因素，再重新執行最小驗證。
3. 同一方向嘗試兩次仍沒有新證據，就停止並求助。
4. 不用刪除測試、忽略錯誤或寫死結果來假裝成功。

## 快速處置表

| 故障 | 先檢查 | 降級方式 | 何時通知隊長 |
|---|---|---|---|
| Codex/API 無法使用 | 官方狀態、網路、個人額度、錯誤碼 | 保留規格，先做人工作業或切換不依賴呼叫的任務 | 10 分鐘內未恢復 |
| Skill 無法呼叫 | 名稱、安裝位置、凍結版本 | 直接讀該 `SKILL.md`，人工照步驟執行 | 流程或輸出與隊友不同 |
| SSH/A6000 中斷 | 網路、主機、GPU、磁碟與現有程序 | 使用本機小規模設定或已驗證的 cached demo | 兩次重連失敗或工作遺失 |
| 測試持續失敗 | 第一個錯誤、最近 diff、環境版本 | 回到最小失敗案例，使用 `diagnosing-bugs` | 兩次假設都被證據否定 |
| Git 衝突 | 是否改到同一檔案、各 branch 目的 | 暫停合併，由 owner 與兩位作者一起處理 | 立即 |
| Demo 即時結果不穩 | seeds、延遲、資源與輸入 | 切換預先驗證的固定案例或 cached replay，清楚標示 | 無法在預定時間內穩定重現 |

## Secret 外洩

若 secret 曾出現在 prompt、terminal 分享、issue、commit 或 log：立即停止使用並通知 owner，撤銷或 rotate 該 secret，再清理暴露位置。只把文字從最新檔案刪掉通常不夠，因為 Git 歷史或外部服務可能仍保留內容。
