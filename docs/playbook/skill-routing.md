# Skills 情境對照表

本頁是「先選對流程」的快速入口，不是每個 skill 的完整教學。實際可用的 skill 名稱與版本，以團隊凍結的 manifest 為準。

## 使用原則

- 一次處理一個清楚、可驗收的目標；不要因為 skills 很多就全部使用。
- 選擇 skill 前，先確認目前是釐清、實作、除錯或驗收階段。
- skill 的建議不會取代人對 diff、來源與結果的檢查。

| 遇到的情境 | 建議使用 | 不適用的情況 | 預期產出 |
|---|---|---|---|
| 想法、需求或名詞仍模糊，需要共同決定 | `grill-with-docs` | 已有清楚且小的實作任務 | 共同理解、必要的名詞與決策紀錄 |
| 要做一個明確行為，且可先寫測試 | `tdd` | 需求或成功條件尚未確定 | 失敗測試、最小實作與重構 |
| 問題難以重現、是偶發錯誤或回歸 | `diagnosing-bugs` | 已能直接指出小範圍修正 | 可重現證據、原因與回歸測試 |
| 要檢查變更是否符合要求與既有標準 | `code-review` | 尚未有可供檢查的 diff | review 結果與需修正事項 |
| 需要查證外部事實或案例 | `research` | 問題可由 repo 內既有文件回答 | 附直接來源的研究筆記 |

## 新增或修改對照項目的核可條件

每一項都要能說明：何時使用、何時不要使用、使用後應得到什麼結果。若內容來自 owner 的實務經驗，應依 [Codex 實務經驗](codex-practices.md)的核可流程檢查後再加入。
