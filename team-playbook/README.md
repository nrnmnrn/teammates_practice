# 團隊分工介面

本目錄只提供比賽前後團隊內部建立分工表的參考格式。它不是 `build-handoff/` 的內容，也不是未來實作 repo 的規格。

## 使用門檻（Gate）

開始填寫分工前，必須已有下列輸入：

1. 主辦方已直接確認、且仍有效的賽制事實：總時長、Demo 開始與結束、提交與展示限制。
2. 團隊已決定的共同目標、不做範圍、詞彙、凍結介面與決策 owner。
3. 每位可投入成員、可交付成果、相依關係與可提供 review 的人。
4. 團隊已採納的操作做法及其 practice ID（做法識別碼）。

任一輸入未確認，停止分工。先記錄缺口、取得直接來源或團隊決策，再重新開始。

## 不變條件

- 每個可交付成果只有一位人類主要負責人；AI 是工具，不是責任人。
- 每列都必須可檢查：有輸入、完成證據、reviewer、交接點及失敗備案。
- 共同詞彙、凍結介面與決策 owner 未寫明前，不得平行派工。
- 只有團隊明確採納的 practice ID 可以作為派工依據；研究中的候選、觀察或未採納做法不可使用。
- 分工表不可把研究結果寫成 Sea × OpenAI 台灣站規則、產品需求或實作決策。
- 未確認活動時長前，不寫固定時間百分比；只寫里程碑與其前置條件。

## 填寫順序

1. 完成 Gate 輸入。
2. 先填表頭的共同意圖與邊界。
3. 定義里程碑、凍結介面與決策 owner。
4. 以可交付成果建立每人一列，補足相依、完成證據、review、交接與備案。
5. 檢查 practice ID 均為已採納做法，再由決策 owner 確認。
6. 在各交接點重新檢查相依、介面與 Demo 可執行性；需要時由 owner 裁決調整。

## 停止理由

遇到下列任一情況，停止新增或改派工作：

- 主辦方資訊、共同目標、介面或決策 owner 尚未確認。
- 任一列缺少主要負責人、完成證據、reviewer、交接點或備案。
- 需要依賴未採納、未知或僅屬研究的 practice ID。
- 相依交付物無法在下一個里程碑前取得，且未選定備案。
- Demo 範圍或截止條件改變，但表頭未同步更新。

先修正缺口並重新確認，再恢復分工。研究背景見 `docs/research/`；其內容只屬參考先例或研究觀察，不是台灣站規則，也不自動成為產品需求。

## 模板

以 [work-allocation.md](templates/work-allocation.md) 建立每次的空白分工表。填寫後仍須依本頁 Gate、不變條件與停止理由檢查。
