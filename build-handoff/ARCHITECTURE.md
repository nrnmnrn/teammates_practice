# Codebase 架構與用途

狀態：本包沒有競賽程式。下列責任源自 [PRD §5](PRD.md#5-同程序-python-後端契約)，是預定架構，不代表檔案或模組已存在。開賽後，每次建立或移動實作位置，在相應列補上實際路徑；未實作列維持「未建立」。

## 責任地圖

| 部分 | 用途與責任 | 實際路徑 |
| --- | --- | --- |
| 啟動入口 | 依明確來源建立後端；team 缺 factory 明確失敗 | 未建立；PRD 指定交付入口為 `app.py` |
| BackendAdapter 與 factory | 將隊友後端或明確選擇的本機模型接到同一契約；每個瀏覽器 session 獨立建立 | 未建立 |
| 排程與領域狀態 | 訂單生命週期、派工、注入、策略、事件、指標與 Mock；後端是狀態權威 | 未建立 |
| Session controller | 所有操作共用序列化入口；讀取一致快照，管理播放、舊回應防護及錯誤復原 | 未建立 |
| Gradio 畫面 | Arena、Metrics & Code、Library；控制項送操作、畫面呈現已接受的狀態 | 未建立 |
| 契約與串接測試 | 以同一明確資料分別驗證 local 與 team；驗證真實來源與失敗處理 | 未建立 |

以上分類供定位責任，不要求每列另建資料夾或新抽象；實作時沿用已存在且符合契約的程式。具體子 PRD 拆分、owner、順序與相依待團隊決定。

## 資料流與共用介面

1. 使用者操作 Gradio 控制項，或單一播放更新來源提出操作。
2. Session controller 檢查當前世代與鎖定狀態，序列執行 BackendAdapter 操作。
3. 相容層呼叫實際選定的後端，並依 PRD 統一快照、技能與例外。
4. Controller 在同一序列區間取得完整 snapshot 與 skills，附上更新版本，交給三個畫面。
5. 畫面只接受目前世代及未過時的更新；動畫只在已知快照間插值，不自行派工或重算權威指標。

方法、型別及失敗語意以 [PRD §5.1–5.7](PRD.md#5-同程序-python-後端契約) 為唯一規格；測試使用同一介面。修改共用介面時，先核對受影響驗收案例並協調同檔寫入者，不能為單一畫面另造契約。

## 未知與更新責任

- 隊友實際 factory、模組位置與依賴：開工時由後端提供者補齊於串接文件及相應 issue。
- 檔案位置與測試入口：實作者建立時更新本表；未存在的命令不得宣稱可執行。
- 真正自主適應 AI 的範圍與證據仍待全隊界定；本架構不新增 Agent loop、learning pipeline 或完整 evaluator。
- README 管啟動；CONTEXT 管詞彙；本檔管實作責任與位置；GitHub 管執行狀態。狀態以證據更新，不因架構表已寫好而視為完成。
